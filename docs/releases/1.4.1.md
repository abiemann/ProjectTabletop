# Project Tabletop 1.4.1

Board setup now illuminates the board immediately and checks camera exposure and colour before play. This update uses the existing camera capture and preserves detector thresholds.

## Board setup and camera calibration

- Setup, rescans and exposure retries start with full-white projection. Four separate cardboard edges inside the projector field must remain stable before initialization continues; the initial room-light/black-screen scan is removed.
- A bounded exposure check can brighten a dim white scan or reduce clipping. A setting change waits for settled images and repeats the white edge measurements.
- After the first five alignment dots, shared edge colour bars and grey steps become camera references. Exposure is checked before white balance, with small bounded trials and measured improvements retained. Unsupported controls are skipped.
- A fresh reference and final five-dot pass establish alignment and visual-latency timing at the retained settings. Keep the board still and the edge strips uncovered until the board scene appears.
- Rejected camera writes can continue when readback confirms the original setting. Unverifiable writes stop calibration. Only supported controls already in manual mode are eligible; shutter timing respects the negotiated frame period. ISO, gain, capture format and detector thresholds are unchanged.

The existing automatic brightness/contrast picture profiles remain separate. Switching them off does not disable board-setup camera calibration. Source builds now pin stable .NET SDK **10.0.403**.

## Download and install

Download **ProjectTabletop-1.4.1-win-x64-setup.exe** from the release assets. It targets Windows 11 x64 and includes .NET, the Windows App SDK, native dependencies, models and board media. Setup installs for the current user without administrator rights and preserves existing settings, saved games, learned profiles and exported pictures.

The installer is unsigned. Compare its hash with `SHA256SUMS.txt` from the same release; the payload manifest identifies the packaged files and source commit. See the [installation guide](https://github.com/abiemann/ProjectTabletop/blob/v1.4.1/docs/INSTALL.md) and [camera calibration details](https://github.com/abiemann/ProjectTabletop/blob/v1.4.1/README.md#automatic-camera-calibration-during-board-setup).

## Validation and limits

Local validation before packaging passed the **1,288-test offline suite**. After the final adjustment, all **34 focused camera-calibration checks** passed again; these counts overlap. The final application build had zero warnings or errors. A saved dim Facecam scan correctly requests exposure -7 to -6 at 60 fps.

Live white-first setup completed on the development tabletop without a false camera-freeze warning. Exposure writes worked, and final alignment had center-check error **0.0012**. At exposure **-6**, all four edge strips were readable with brightest-grey channel level **235** and no sampled clipping. The user confirmed that laser aiming and shots work; captured play records a **Target Practice paper-target hit** and a **HUNT bird hit**. These observations do not establish coverage of every target or a statistical shot-success rate.

The tested Facecam driver advertises white-balance support but rejects changes. Readback confirmed its original **3400 K** after a rejected 3700 K trial, allowing setup to finish. White balance remains unchanged; no accepted white-balance correction is claimed. Camera/projector/room combinations and sustained capture reliability still require their own physical acceptance. A real capture stall retains the existing explicit Stop/Start recovery requirement.

The Windows release workflow will rerun the current offline suite, verify the payload, and check installation, startup, navigation, GPU preview rendering, shutdown and uninstall before publication. The local evidence above is separate from that workflow; its success must be confirmed from the release run.
